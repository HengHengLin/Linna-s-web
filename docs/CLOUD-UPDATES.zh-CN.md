# 云端内容更新约定

## 公开数据与读取

公开仓库为 HengHengLin/Linna-s-web，分支 main。原始内容在 content/public/*.md，部署的 React 网站读取 public/content.json。打开网站、窗口重新获得焦点及每十分钟都会同步；GitHub CDN 可能造成短暂延迟。同步失败时显示已有内容和失败提示。日常内容更新无需重新部署网页。

public/content.json 格式是 {"schemaVersion":1,"updatedAt":"含时区 ISO 时间","entries":[]}。entries 每项等于 Markdown 的 JSON 元数据加 body 字符串，按日期降序、同日按 id 排序。字段规范见 CONTENT.zh-CN.md、src/public-content.js 和 scripts/content.mjs；现有真实 lesson 可作格式参照。journal 指公开学习总结，绝不代表私人交易日志。

## 无人值守更新

1. 每次从远程 main 读取最新提交及本文、内容格式规范与全部公开内容；不要从旧本地快照覆盖云端。确认当前云端执行环境可读取并写入这个 GitHub 仓库。连接不可用时停止写入并报告失败，不能把本地文件修改或任务保存当作同步成功。
2. 在线检索并实际阅读资料，优先官方机构、研究论文、公司公告或原始视频。核验链接、发布日期和事实，写出引用来源；不编造时长、逐字稿、字幕或价格。北京时间决定文章日期。
3. 使用确定性 id，例如 lesson-YYYY-MM-DD-主题，briefing-YYYY-MM-DD 或 topic-YYYY-MM-DD-主题。重试更新同一条，不重复添加。保留历史记录。自动内容只能使用 curated、ownerViewpoint:false、sourceVerified:true，不修改 Linna 的 approved 文章，不伪造学习完成、用户总结或审核信息。
4. 同一次提交保存新 Markdown 及由全部 Markdown 生成的完整 public/content.json。可以在临时检出中执行 npm ci、npm test、npm run build 并正常提交推送；或者使用 GitHub API 创建基于最新树的变更树、提交和非强制分支更新。API 写入时也必须核验全部字段、来源、唯一 id 与正文，JSON 不得遗漏旧文章。
5. GitHub API 使用最新 main 为父提交并以该 SHA 做 expected_sha；遇到并发变化，重新读取远程后合并本次内容再重试，禁止 force。不得把凭证、私人草稿、交易记录或聊天原文放进公开文件。安全字段只表达流程，不替代真实授权。
6. 写入后重新读取远程 Markdown 与 public/content.json，核对文章 id、正文、更新时间及历史保留。失败不能报成功。同步失败时保留已有内容。

## 内容范围

- 每日金融英语：一条核验的英文金融视频或带视频的官方页面，中文简介、金融知识、词汇、地道表达与输出练习。每周至少一次 Crypto 演讲精听，只有核验实际片段后才提供时间戳。
- 每日财经简报：宏观、股票、Crypto，标注来源及更新时间。仅做事实摘要与明确标注的待验证问题，不冒充 Linna 的个人投资观点。不提供虚构实时行情。
- 研究选题：每次 3–5 条有来源的候选题，说明为什么值得研究、核心问题、可查证资料和反方解释。覆盖 AI 与生物医疗、航空航天、威科夫与量价分析，也兼顾宏观、Crypto/RWA 与 DeFi。交易方法材料用于学习，不写成买卖指令。
- Linna 发来的学习总结：由交互式对话按授权归档一句话、讨论主题、知识、纠正和下一步练习；云端定时任务不得自动读取私人聊天或编造总结。
- Linna 要求删除选题：同时删除对应 Markdown 和 JSON 条目，验证远程读取。下一次静态版本更新同步清理离线后备内容。
