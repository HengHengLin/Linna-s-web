## 确认后的合并与部署方案

1. 再次获取真实最新 main；若 Git 传输仍失败，重新用 API 完整树核验。远程内容变化必须保留；无法证明安全即停止。
2. 优先从真实最新 main 创建发布分支，把相对已核验生产树的 Beta 增量应用为独立提交。不要直接强制合并本地镜像历史，不使用 force push。可从 `git diff --binary e356581 release/beta-20261028` 导出候选增量，应用前核对文件列表，应用后对最新内容及同步文件逐字校验。若 API 完成提交，则以最新远程 parent 创建树并只修改审核过的增量路径；同样保留最新每日文件。
3. 运行生产构建及快速测试，通过普通 PR 合并 main；届时 GitHub Actions 的 Pages 工作流构建 dist 并部署 GitHub Pages，既有权限不变。现在不创建或推送 PR。
4. 部署后核对六入口、一个模型、56 条或届时最新内容数量、最新简报和同步时间，再确认 Beta 生效。线上地址 `https://henghenglin.github.io/Linna-s-web/#/home`。
