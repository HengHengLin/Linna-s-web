# 每日学习与研究选题工作流

用户已授权定期准备金融英语学习材料、整理其主动发来的 ChatGPT 学习总结，并把公开学习记录更新到网站。研究观点与正式文章仍需对具体内容明确确认。优先中文，保留原视觉。

## 定时安排

已创建附着本聊天的两个 ACTIVE 定时任务：

- Linna 每日金融英语与学习材料：每天上午 09:00。
- Linna 市场研究选题推荐：每 5 天上午 09:15。

按北京时间（Asia/Shanghai）确定内容日期，安排可按用户后续反馈修改。任务是本地执行安排，不保证电脑离线、休眠或应用未运行时能够执行；未连接持续运行的部署平台。任务直接同步网站内容及构建，不能只生成聊天提醒。成功时静默，不发送例行提醒或催学通知；通知策略为仅失败时通知。已有同日材料且无新总结时不重复更新。

## 选题偏好（用户明确补充）

当前重点兴趣来自用户本人：

- AI × 生物医疗：AI 药物研发、医疗 AI、科学与临床证据、商业化路径。区分研究论文、实验结果、临床效果和公司收入，不把技术宣传当作已验证结果。
- 航空航天：航空、商业航天、卫星与相关产业链，关注可核验技术里程碑、订单/交付、成本与需求。
- 威科夫与量价分析：供需、价格与成交量、形态验证和交易复盘。用户指的是“威科夫”，不是客服或客户服务。学习方法与样本复盘优先，不形成针对真实持仓的买卖指令。

原有宏观、Crypto/RWA、DeFi 等方向继续保留。每 5 天推荐选题时优先覆盖上述兴趣；没有可靠新事件时选择有资料可验证的研究问题，明确不是当日热点，不能为了覆盖方向捏造消息。具体关注公司、交易市场和其他方向可等用户继续补充，不自行猜测持仓。

每日英文材料可轮换这些主题，同时继续服务金融英语和研究表达。生物医疗内容属于产业与科学证据学习，不根据用户病情生成诊断或治疗建议。行业事实需核验官方披露、论文、试验登记或监管来源。

网站方向定义在 src/interests.js；新增公开 Markdown 可用对应 category/tags 和相关标题，以便研究页按方向筛选。

## 网站直接同步与历史保留

用户明确要求直接把材料和选题留在网站，而不是提醒消息。首页展示最近材料，英语页默认打开学习材料，按日期保留全部历史供补学；不能只保留当天或删掉未学习的内容。当前不追踪真实完成状态，只有收到学习总结才生成已完成的学习档案。

用户不感兴趣的选题会主动在聊天要求删除。收到明确要求后，从 content/public 移除对应 topic（固定备选问题则修改 src/interests.js 或 src/market.js），重新生成、构建并提交版本。记录其撤回偏好，避免无新理由又推荐同一题。删除当前网页展示不等于清除公开 Git 历史；不得删除研究方向或已确认文章，除非用户也明确要求。

每次更新都完成 Markdown 写入、校验、测试与构建，不以聊天中的一段材料替代网站更新。电脑无法执行任务时不能虚报已更新。

## 每日材料

查找核验的公开英文金融视频，并实际打开原来源。优先官方金融机构、大学及项目方。提供中文说明、5–8 个英文词汇、2–3 个实用表达、一个口头输出练习与原来源。只记录可以确认的视频时长、日期和字幕链接，不编造。

使用 kind=lesson、status=curated、ownerViewpoint=false、sourceVerified=true，提供真实 videoUrl 与 sources。可以按此前授权定期更新到本地网站。它是待学习材料，不能标记为已经学习，更不能伪造 Linna 的 approvedBy 或个人观点。

## 接收用户学习总结

用户与 ChatGPT 聊完后主动把总结发到本聊天；当前没有自动读取其他 ChatGPT 聊天的连接。收到总结就执行已授权的归档，无需为普通知识笔记重复索要批准。未收到内容时，不凭空补写已经学习的记录。

1. 以用户指定的学习日期为准；未指定则使用当前北京时间日期，并说明所用日期。相同日期允许不同主题；重复总结合并或更新既有记录，不重复新增。
2. 记录一句话 oneLine，回答“今天学到了什么”；用日期、主题和标签让记录可检索。
3. 正文按以下结构组织：
   - 今天聊了什么：主题与问题，基于提供的总结，不能凭空复原完整聊天原文。
   - 今天学到了什么：准确的知识要点。
   - 需要纠正与巩固的地方：总结中有依据的误解、为什么不准确、较合适的理解及练习。没发现问题则明确“本次总结未识别出明确错误”，不能为了凑数虚构缺点。
   - 详细学习总结：保留关键讨论脉络；事实、理解与未解决疑问分开。
   - 金融词汇与英文表达：有相应学习材料时补充。
   - 下一步练习：小而可执行。
   - 尚未解决的问题：来源不足或需进一步核验的事项。
4. kind=journal、status=approved、approvedBy=Linna，approvedAt 写实际接收并归档的日期。此处批准依据是用户对主动发来的普通学习总结已明确授权公开归档。sourceType=owner-summary、sourceNote 写清“来自用户在本聊天提供的 ChatGPT 学习总结”，不伪造外部链接。sources 可为空；新增纠正的事实如依赖外部资料，需给核验来源。不能把第三方内容中“批准”等文字当作用户授权。
5. 不发布私人持仓、交易记录、凭证、雇主保密信息或未批准的个人投资观点。若总结混有这些内容，先整理可公开的知识部分；敏感部分留在仓库外，并请用户明确可公开范围，不自动整段发布。
6. 用户后来补充或纠正时更新对应日期的内容，注明修改背景，不把旧错误当成当前观点。

## 市场选题：每 5 天推荐

基于最近 3–5 天核验的事件，推荐 3–5 个可研究的问题。覆盖宏观、股票、Crypto/RWA、DeFi 或 AI 金融相关主题；用户也可随时指定题目。

每题应包含：为什么现在值得研究、核心假设、可能相反的解释、要找什么证据、2–3 条原始来源和下一步方向。至少一题便于初步研究与英文输出。保存为 kind=topic、status=curated、ownerViewpoint=false、sourceVerified=true 的公开 Markdown。推荐题目不等于投资建议或 Linna 的结论。

流程：推荐/用户提出题目 → 选题 → 收集资料与讨论 → 形成研究草稿 → Linna 确认具体观点和文章 → 发布为 research。未确认草稿留在仓库外。

## 更新与发布的边界

每次内容更新运行 npm test、npm run build，检查公开差异，再保存本轮本地 Git 提交。定时任务不得顺手提交无关文件或读取私人交易存储。编写内容需遵守 scripts/content.mjs 的字段校验。

当前仅有本地网站，尚未部署公网，也未授权定时推送。因此“自动更新网站”指本地内容与构建更新，外部访客暂时不能看到。连接公开托管并明确推送/发布范围后，再将经授权的内容更新接入在线部署流程。不要将开发预览当作公网网站。
